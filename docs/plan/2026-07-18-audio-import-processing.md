# 音频导入处理闭环

状态：已完成（2026-07-18）

## 目标

把已经存在但尚未接入 UI 的音频分析、代理生成和波形 peaks 生成能力接到导入流程。导入完成后，素材应立即具备真实时长、播放代理和可用波形，不再等到第一次落轨时才补分析。

## 范围

- 新增 renderer 侧的导入后处理编排：`analyze -> parallel(proxy, peaks)`。
- 导入原文件成功后再启动处理，任何处理失败都不能删除或回滚原始素材副本。
- 成功时刷新 workspace 和素材库，并显示明确完成提示。
- 失败时保留素材，显示“已导入但处理未完成”的具体错误。
- 保留落轨时的时长分析兜底，兼容旧项目和历史未分析素材。

## 不做

- 不接入实际转写或降噪。
- 不增加后台任务队列、取消按钮或断点续传。
- 不改变 proxy、peaks 文件格式和本地文件契约。
- 不修改导出逻辑。

## 完成标准

1. 单元测试证明分析先执行，proxy 和 peaks 只在分析成功后执行。
2. 处理失败时调用方能区分“导入失败”和“导入成功但处理失败”。
3. 浏览器 mock 或真实 Electron 中导入后素材立即显示真实元数据；播放数据包含 proxy 和 peaks。
4. 全量测试、类型检查、生产构建和差异检查通过。

## 验收结果

- 导入后素材库立即显示 `0:07 · 双声道 · 48 kHz`。
- 素材落轨后时间线长度为 `0:07.17`，并显示生成后的波形 peaks。
- 浏览器 mock 控制台无 warning/error。
- 处理编排测试覆盖成功顺序和分析失败短路；旧项目仍保留落轨时长分析兜底。
